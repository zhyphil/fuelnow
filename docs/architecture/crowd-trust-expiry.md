# P6-CROWD-05 — 可信度、防滥用与过期机制设计

2026-09-07。设计完成，尚无生产众包数据、审核队列或清理任务。适用于 [价格确认](./crowd-price-confirmation.md)、[营业设备观察](./crowd-operational-confirmation.md)、[费用反馈](./crowd-fee-feedback.md) 与 [照片审核](./crowd-photo-review.md)。本文件不等于处理者/法律依据/保留政策已经获批。

## 状态与权限

| 当前状态 | 允许流转 | 是否可影响推荐 |
| --- | --- | --- |
| draft（仅内存） | 用户提交 → pending；离开 → 丢弃 | 否 |
| pending | 服务端验证/风控 → in_review 或 rejected；用户 → withdrawn；超期 → expired | 否 |
| in_review | 有权审核者 → approved / rejected / needs_info；用户 → withdrawn；超期 → expired | 否 |
| needs_info | 用户补充为新版本 → pending；撤回/到期 | 否 |
| approved | 更晚的合格证据 → superseded；到期 → expired；撤回 → withdrawn；复核 → in_review | 仅通过全部字段/许可/时效/能力门槛后，以独立来源提升 |
| rejected / withdrawn / expired / superseded | 终态；若重新观察则新报告，不能重开旧报告续期 | 否 |

服务端白名单禁止客户端传状态、审查人、可信分、approvedAt 或 expiresAt。提升要在事务中重新确认状态版本、观察期限、来源版本及许可/能力；同一报告/字段/版本唯一，审查不可自审，高风险修改需双人。outbox 和缓存 generation 在同一事务登记；迟到任务、并发审核、重复消息或撤回不得绕过版本检查。

先保存候选层，再创建独立 `user_observation` 来源及字段 provenance。不得用官方 source ID 写入、不修改官方原记录、不自动合并站点。已有 SourceRecord/字段归属、生命周期和搜索证据门槛仍保留。是否启用新的可决策来源需迁移、契约、读取逻辑与真实审核链路验收，不能仅新建一张反馈表就视为完成。

## 可信度规则

- 未核实匿名报告：low / pending，不给 Best 正分，不标 Verified/Live；照片/OCR 高置信也不升级事实可信度。
- 人工确认字段、单位、范围、观察时间且证据合格：最多 medium 的独立观察候选；不是统计概率。Verified 标记只在真实审核完成且未过期后，保留审核及观察时间的区别。
- 多个报告只有可证明独立且内容/时间一致时才作佐证；cookie/令牌不同、IP 不同或多数投票不能证明独立用户。不能靠刷量自动晋升 high。
- 与较新官方/运营证据冲突：保留待复核，不按“最后收到”或票数覆盖；负面故障需范围明确，单设备故障不能封全部服务。
- 商家、自报身份或利益相关反馈单独标记，身份未验证时不声称官方；不引入付费置顶或买可信分。
- 高可信、短时、多数确认均不能修复未知币种/单位、失效许可、缺精确服务范围或 EV 动态能力不足。

## 防滥用与最小数据

核心搜索/导航免登录不变。未来匿名写入使用短期随机贡献能力令牌、服务端限速和幂等键，不使用广告 ID、设备指纹、GPS 轨迹或后台位置。令牌仅用于私有反馈风控/撤回，不混入产品行为分析；匿名意味着不能可靠确认一个自然人，必须保留这个限制。

保守初始防护设计：每令牌每日 5 个待审报告、同站点/字段每小时 1 个、全局队列和上传预算上限；实际额度启用前需压测与运营批准。共享网络不得仅因 IP 就定罪；确需网络级风控时单独审批短期轮换 HMAC/最长 1 小时的桶，不存原 IP 到反馈内容或日志，不将哈希误称匿名化。无批准时不启用对应收集。

同幂等键同内容返回原回执、不同内容冲突；重复内容可减少重复审核工作，但不能吞掉新观察时间或用户撤回。返回枚举错误/限速等待时间，不能泄露他人的反馈存在与私有 ID。图片随机对象名、受限读取；未来写接口还需认证/令牌作用域、请求大小、CORS/CSRF（若采用 Cookie）、枚举/重放与授权绕过测试，不能把现有公共读接口保护当作写接口验收。

## 有效期设计默认值（非已上线配置）

| 观察字段 | 活跃证据最长时效 | 附加规则 |
| --- | --- | --- |
| 某次 open/closed 观察 | 15 分钟 | 不替代一周排班/节假日日历 |
| 当前占用/available 观察 | 5 分钟 | 不自动获得官方 EV Live 能力 |
| 设备 working/broken 观察 | 1 小时 | 到期归未知，不假设已修好或继续坏 |
| 明确产品/条件价格 | 24 小时 | 原有更严格来源/价格门槛优先 |
| Free/Paid 与顾客限制 | 7 天 | 仅静态费用属性，不延长实际金额/设备时效 |

`expiresAt = observedAt + min(本策略 TTL, 适用领域更严格 TTL)`；基于用户观察时间，而非 receivedAt、审核、重试、重新抓取或相同投票时间。不知道观察时间则不可提升活跃证据；未来时间需重选/复核，不“修正”为现在。审核完成时已经过期则只保留获批期限内的历史审查记录，不能发布新鲜值。

读取时强制检查 expiresAt/状态，清理作业延迟不能让过期值继续参与推荐；缓存按证据失效时间限制 TTL，到期/撤回/复核触发失效并保留原因。撤回/过期后仅回退到其它仍合格的独立来源，否则 Unknown；不自动恢复已失效的旧官方数据。历史审计留存与活跃证据 TTL 是不同概念。

## 撤回、删除与审计

私有回执内提供随机撤回凭证，服务端只保存校验摘要并做访问限制；匿名用户丢失凭证后的申诉渠道待批准，不承诺一定可找回。撤回使候选/提升资格立即失效；照片、衍生文件、OCR 文本和缓存分别排队删除并确认，失败重试和告警。备份的保留/恢复后重新执行撤回清单需部署方实测，不能承诺尚未配置的备份删除期限。

审计只保留经批准的最小报告/版本/动作/授权角色/时间/固定原因，不保留原图、用户起点、原始异常或任意输入。公开 Beta 报告仅汇总，稀疏分组可能关联个人，发布阈值与处理责任仍待确认。

## 设计验收走查

1. 同一人重试或换令牌刷量：不能得到多份独立证据或自动 high。
2. 上传者伪造 approvedAt/confidence：拒绝字段，只有受控审核可提升。
3. 审核任务晚于 expiresAt：不得发布，重试不续期。
4. 用户撤回同时审核通过：版本/事务检查保证撤回资格优先，已发布缓存失效。
5. 多设备中一个故障：只存具体范围，不关闭全站或其它服务。
6. 清理作业失败/缓存仍有旧值：读时过期/状态检查保护，不能仅依赖定时清理。
7. 匿名小样本或共享 IP：标识能力不足，不虚构独立参与者或误封核心搜索。
