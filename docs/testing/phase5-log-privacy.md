# Phase 5 — 应用日志与分析数据最小化

2026-09-07；P5-LEG-06 完成当前应用实现范围的审计。部署网关及未来第三方监控必须在 REL-02 接入时重新验收；本记录不宣称任何云平台已配置合规。

## 数据边界

| 输出位置         | 保留                                                                    | 禁止                                               |
| ---------------- | ----------------------------------------------------------------------- | -------------------------------------------------- |
| API 请求完成日志 | 服务端 request ID、方法、路由模板、状态码、耗时及日志基础时间/进程字段  | 原始 URL/query、请求头/body、来源 IP、坐标、地址   |
| API 非预期错误   | 固定 internal_server_error                                              | 异常 name/message/stack/cause，可能含 SQL 或请求值 |
| 同步任务失败记录 | 白名单错误代码、固定 Source import failed、run ID、计数、状态和重试安排 | 自由文本错误、未知错误名称、URL、凭据              |
| 本地产品事件     | 白名单服务/排序/结果数量/公共站点 UUID/成功标志                         | 坐标、地址、任意属性、设备或广告标识               |

API 禁用自动请求日志，显式拒绝客户端提供的 request ID 作为日志关联标识；404 不记录攻击者构造的路径。同步错误不仅在导入层过滤，也在 PostgreSQL reporter 写入边界再次限制。原异常仍会抛给调用方用于控制流，调用方不得自行打印完整异常。

客户端事件默认关闭，只在用户启用后留存最多 100 条、15 分钟，关闭或进程退出即清除；没有远程分析 SDK、上传或磁盘落地。已复核 recorder 和 UUID 校验及既有 opt-in/容量/过期测试。

## 验证

新增 9 项回归：实际 Fastify 日志在 200/400/404/413/429/500 路径中不含植入的精确坐标、地址、凭据、请求头或异常内容；未知异常类别降为 UNKNOWN_ERROR；同步普通失败与重试失败两种 SQL 写入均不保留原始错误。337 个 API tests、类型和 lint 通过。

## 部署验收要求

- 搜索仍使用 GET 参数，反向代理、CDN、负载均衡器、APM 必须禁用或移除 query、原始路径/请求头/body、精确坐标；应用不打印不代表平台不会采集。
- 禁用自动面包屑、请求体、截屏/会话重放和客户端位置采集；新增 SDK 要重跑隐私检查。
- 日志保存期限和访问权限由实际处理方落实，不能把 ADR 默认上限当作已经部署的删除策略。
- 源站坐标属于业务公开站点数据；用户出发点不得被混入来源原始数据或同步任务输入。
- 历史库如已保存旧错误文本，需要在真实环境识别范围并获授权后清理；此次没有删除现有数据。

参见 [ADR 0007](../decisions/0007-location-privacy.md)、[ADR 0015](../decisions/0015-local-test-events.md)。
