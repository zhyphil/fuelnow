# Phase 5 — 隐私安全 API 错误率与延迟汇总

2026-09-07，REL-02c。只提供离线应用日志样本分析，不选择监控服务、不上传日志、不启动常驻采集。

`pnpm --filter @fuel-now/api operations:logs` 从标准输入读取 JSON lines；不会自行查找用户日志或读取任意路径。仅处理固定消息 API request completed，按时间、状态码、响应耗时汇总。输入上限 2 MiB/10,000 行，单行上限 16 KiB，超出总预算拒绝；错误输出为固定提示，不回显输入。

固定 route 维度只有 /v1/nearby、/v1/service-points/:id、/openapi.json、other，其他路径不回显，不保留 request ID、地址、坐标、请求头、异常文本或原始事件。每组输出请求数、5xx、4xx、429、5xx 比例和 nearest-rank p50/p95/p99 毫秒。按各 route 检查，防止高流量正常端点掩盖低流量故障端点。

默认观察窗口最近 5 分钟，拒绝未来/窗口外事件进入样本；不足 20 个请求显示 insufficient_samples，空输入的错误率和延迟是 null，而非“零错误、零延迟”。损坏记录单独提示。暂定审查阈值为 5xx 比例 ≥5%、p95 >1,000ms，429 单独提示；这些是可配置样本审查阈值，不是承诺的生产 SLA。

exit 2 表示需要关注或证据不足；exit 1 是输入/计算失败；exit 0 仅说明这一输入样本未触发上述阈值，始终 releaseAuthorized=false。日志缺失但仍有部分样本、重复汇集、时钟偏差、采样/截断不能据此证明不存在故障；实际部署需要日志流完整性、时钟同步、连续窗口和监控自身失联告警。不要把重叠的日志批次重复合并。

9 个新增测试覆盖无数据、统计边界、429、固定维度与敏感字段不输出、无效输入、窗口、资源限额、端点故障不被全局掩盖，以及真正 Fastify 500 请求产出的安全日志格式。缺处理方、收件人、保存策略和实际环境的部分继续留空。
